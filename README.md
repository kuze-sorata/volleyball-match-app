# Volley Board

バレーボールクラブの運営者向けに、9ラウンド・3コートの対戦表を生成するローカルWebアプリです。時間・スコア・勝敗は扱わず、ホワイトボードへ転記しやすい対戦カードとラウンド進行に集中します。

## 起動方法

```bash
pnpm install
pnpm dev
```

表示されたローカルURLをスマートフォンまたはPCのブラウザで開いてください。

## テスト

```bash
pnpm test
pnpm build
```

`src/domain/scheduler.test.ts` に、要件定義書の受け入れ基準T01〜T12に対応するスケジューラテストを用意しています。

## GitHub Pagesへの公開

GitHub Actionsで`pnpm build`を実行し、生成された`dist`をGitHub Pagesへ自動公開します。`main`ブランチへpushするとデプロイされます。

## 操作方法

1. アドバンス／ビギナーのチーム数を入力して「対戦表を生成」します。
2. 対戦表をホワイトボードへ転記します。コート1はアドバンス、コート3はビギナーです。コート2は自動配分されます。
3. ラウンドの実施後、「このラウンドを終了」を押します。終了済みラウンドは履歴として固定されます。
4. 途中参加は「変更」に入力し、「差分をプレビュー」してから確定します。コート2は常に自動配分され、終了済みラウンドと進行中の内容は保持され、未開始ラウンドだけが更新されます。
5. データはブラウザのlocalStorageへ自動保存されます。別端末との同期は行いません。

## 公平性の評価指標

- ハード制約：カテゴリー混合禁止、コート1／3固定、同一ラウンド内のチーム重複禁止、参加前チームの配置禁止。
- 優先順位：参加可能期間を考慮した試合数の偏り、同じ相手との重複、連続出場の偏り、成立試合数の順で評価します。
- 同条件・同seedで同じ表を再生成できるよう、候補選択にseed付きの決定的な揺らぎを使います。

## 既知の制約

- 初期版は1ブラウザ内のlocalStorage保存です。サーバー同期、複数端末同時編集、ログインは対象外です。
- 入力数が非常に多い場合は、ブラウザ上での計算時間が増える可能性があります。
- ラウンド内に実施しないカードを個別選択する機能はなく、生成されたカードをラウンド終了時にまとめて履歴化します。
