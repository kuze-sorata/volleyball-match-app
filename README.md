# Volley Board

バレーボールクラブの運営者向けに、受付人数とチーム数を記録し、9ラウンド・3コートの対戦表を生成するWebアプリです。時間・スコア・勝敗は扱わず、ホワイトボードへ転記しやすい対戦カードとラウンド進行に集中します。

## 起動方法

```bash
pnpm install
pnpm dev
```

表示されたローカルURLをスマートフォンまたはPCのブラウザで開いてください。

## テスト

```bash
pnpm test
pnpm build
```

`src/domain/scheduler.test.ts` に、要件定義書の主要な受け入れ基準に対応するスケジューラテストを用意しています。

## GitHub Pagesへの公開

GitHub Actionsで`pnpm build`を実行し、生成された`dist`をGitHub Pagesへ自動公開します。`main`ブランチへpushするとデプロイされます。

## 操作方法

1. アドバンス／ビギナー別に受付人数を記録します。画面には6〜7人編成を目安に、区分ごとのチーム数を表示します。
2. 実際の編成に合わせてチーム数を入力し、「対戦表を生成」を押します。チーム番号はアドバンスが1、2…、ビギナーがA、B…と自動で付きます。
3. 第1ラウンドは、アドバンス1–2をコート1、ビギナーA–Bをコート2、ビギナーC–Dをコート3に配置します。該当チームが足りないコートは試合なしになります。
4. 第1ラウンド終了前に「第1ラウンドを調整する」で実際の対戦カードに合わせられます。「この組み合わせで後半を組み直す」を押すと第1ラウンドを固定して第2〜9ラウンドを再計算し、差分を確認してから確定できます。
5. コート1はアドバンス、コート3はビギナーです。コート2は第1ラウンドのみビギナー、第2ラウンド以降は公平性を考慮して自動配分されます。
6. ラウンドの実施後、「このラウンドを終了」を押します。終了済みラウンドは履歴として固定されます。
7. 途中参加では、追加する区分とチーム数を指定し、「差分をプレビュー」してから確定します。終了済みラウンドと進行中の内容は保持され、未開始ラウンドだけが更新されます。
8. データはブラウザのlocalStorageへ自動保存されます。別端末との同期は行いません。

## 公平性の評価指標

- ハード制約：カテゴリー混合禁止、コート1／3固定、同一ラウンド内のチーム重複禁止、参加前チームの配置禁止。
- 初期配置：第1ラウンドはアドバンス1-2をコート1、ビギナーA-Bをコート2、C-Dをコート3に置きます。第1ラウンド終了前に手動調整した場合は、その内容を固定して第2ラウンド以降を再計算します。
- 優先順位：成立する試合数を最大化し、カテゴリー間の1チームあたり平均試合数の差、各カテゴリー内の偏り、同じ相手との重複、連続出場の順で抑えます。
- 同条件・同seedで同じ表を再生成できるよう、候補選択にseed付きの決定的な揺らぎを使います。

## 既知の制約

- 初期版は1ブラウザ内のlocalStorage保存です。サーバー同期、複数端末同時編集、ログインは対象外です。
- チーム人数の目安は参考表示です。アプリはチーム分けや代表者名を記録しません。
- 入力数が非常に多い場合は、ブラウザ上での計算時間が増える可能性があります。
- ラウンド内に実施しないカードを個別選択する機能はなく、生成されたカードをラウンド終了時にまとめて履歴化します。
- 第1ラウンドの手動調整は第1ラウンド終了前に行います。ラウンド終了後は履歴として固定されます。
